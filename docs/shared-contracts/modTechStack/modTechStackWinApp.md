# I. 主旨目的

定義以 .NET（C#）實作桌面類構件（mod＝建置單元）的標準技術選型 Profile。於 design.md ＜III＞ 以文字標記（`modTechStack: XXX`）標於所屬 mod 方框宣告（formatVersion 3.3；3.1/3.2 legacy 為 ＜II.B.(A).1＞ 之 🧱）、＜C 組態設定.(D) 部署做法＞繼承其建置/測試/散佈指令。

# II. 參考準備

* **適用場景**：Windows 桌面單機程式——常駐系統匣工具、熱鍵喚起查詢工具（如 [sysTechType桌面App] 類型）、離線單機工具。**不適用伺服器**：伺服器類一律 [modTechStackNodeSvr]／[modTechStackPythonSvr]（2026-06-24 移除 DotNetSys 之決策僅針對伺服器用途，桌面不在其列）。
* **語言/框架**：.NET 8 LTS+（C#）；UI 框架**預設 WPF**（Fluent 設計語言相容、AI 生成語料大、透明視窗／覆層／多螢幕支援成熟）；WinForms／WinUI 3 等偏離預設需 docs/adr 說明理由。
* **工具鏈**：dotnet CLI；NuGet 管依賴（鎖定 `packages.lock.json`）；`dotnet format` + Roslyn analyzers；xUnit 測試。
* **產物型態**：**Windows 散佈包**——self-contained 單檔 exe（`win-x64`）為預設；MSIX 為選配（design.md 指定）。

# III. 內容程序

* **資料夾慣例**（建置單元內，生態系慣例優先）：
  * `<App>.sln` + `src/<App>/<App>.csproj`：方案與專案組態。
  * `src/<App>/`：應用程式碼；`tests/`：xUnit 測試（單元測試貼著模組）。
  * 免 Dockerfile（桌面類無容器化需求）。
* **指令（供 design.md＜C 組態設定.(D) 部署做法＞繼承；特殊需求於 design.md ＜C.(D) 部署做法＞覆寫）**：
  * 建置：`dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`（產出單檔 exe 散佈包）。TFM／API floor 須遵下「平台紀律」之 Win10＋Win11 雙兼容約束。
  * 測試：`dotnet test`（xUnit，涵蓋度門檻寫在專案組態）。
  * 散佈：見「散佈方法」。
* **散佈方法（deployWinDist）**：**不走 Helm／K8s**——散佈包以 **GitHub Release 資產**為主通道（含 SHA256 讀回驗證）；winget／其他第三方通道由 design.md 指定（選配）。發佈交付規格見 [2tech-trainFlow-2rel/src/FORMAT.md] ＜3.B節＞。
* **自動更新散佈（Velopack／`vpk`，需背景自動更新之桌面首選）**：定版四步（`vpk` CLI，`~/.dotnet/tools`）——① `dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -o <pub>`；② `vpk download github --repoUrl <url> --channel <ch> --outputDir <rel>`（下載前一版 full nupkg 作 **delta 基準**；**缺此步則無增量**、使用者須下載整包）；③ `vpk pack --packId <Id> --packVersion <VERSION> --packDir <pub> --mainExe <App>.exe --packTitle <Title> --channel <ch> --outputDir <rel> --icon <app.ico>`（產 full＋delta nupkg＋Setup.exe＋Portable.zip＋RELEASES/releases.<ch>.json）；④ `vpk upload github --repoUrl <url> --publish --releaseName "<Title> <VERSION>" --tag v<VERSION> --channel <ch> --outputDir <rel> --token <gh auth token>`（建並發佈 GitHub Release、掛所有資產）。紀律：`packVersion`／`--tag` **沿用 `VERSION`不重算**；跨版 `channel`／`packId` 須一致（否則 update feed 對不上）；未程式碼簽章的 `vpk` 警告**非致命**——不影響既有用戶增量更新，僅全新安裝跑 `Setup.exe` 時 SmartScreen 可能提示一次；build/publish 前須先關閉正在執行的該 app 實例（否則 exe 被鎖、`MSB3027`）。
* **對外介面綁定（硬性）**：桌面原生應用**不錨 [hmiIntf通用視覺規範]**（MD3 web 基座），改錨**宿主 OS 設計語言**（Windows＝Fluent：Segoe UI 字階、4px 間距格、圓角、暗色支援）；可近用性維持 WCAG 對比精神。宣告 sysTechType（如 [sysTechType桌面App]）者，依該契約最低能力清單與介面 bar 逐頁驗收（GATE ＜5節＞ 鏡頭 A＋C）。**solTechStyle 覆寫**：design.md 明選具體視覺風格 [solTechStyle*]（如 [solTechStyle童話手繪風格]）時，該 solTechStyle 覆寫 OS 預設之視覺錨與**圖示語言**（見下「圖示」例外）；覆寫的是外觀與圖示語言，**互動慣例與內建控件紀律（下列各項）仍守**，可近用性/對比精神不減。
* **桌面慣例＝硬性預設（有標準答案不回問）**：技術選型為本 Profile 時，一切依 Windows 桌面慣例逕出版型草稿、USR 只糾偏；「更名原地編輯 vs 對話框」這類**本有慣例答案**者**不得回問 USR**（回問＝把照慣例設計的責任推回使用者）。已固化慣例：視窗標題只在 OS 標題列（不重複）、**主視窗標題列尾端顯示版號**（格式 `<AppName> vX.Y.Z`，如 `LingoIsland v3.1.0`；版號取自 assembly version〔`AssemblyInformationalVersion`／`FileVersion`，其值同步自根 `VERSION`〕，**標題字串不得硬編版號字面**〔防漂移，單一事實來源〕，比照標準 Windows 桌面軟體慣例；適用所有 modTechStack=WinApp 之 sys，驗收循 GATE ＜5節＞ 鏡頭 C 平台慣例逐頁審）、狀態文字置底 StatusBar、樹狀清單＝標準節點＋右鍵選單（新增／更名 F2 原地編輯／刪除 Del）＋頂部建立入口、清單拖曳＝插入指示線＋目標高亮、欄寬可調＝GridSplitter、**可調大小之視窗/對話框＝右下角縮放握把**（`ResizeMode="CanResizeWithGrip"`，內容可能溢出者如進度/日誌/編輯框尤需；固定尺寸小提示框除外）、**長時間運作（>~1s 之網路／AI／CLI／檔案）＝非阻斷進度回饋**（可取消之模態進度視窗，或內嵌 spinner／覆層沙漏；**不得靜默凍結 UI 執行緒**——長工掛 async、進度以 `IProgress`／Dispatcher 回報）、**可選取複製但不可編輯之文字＝無框唯讀 TextBox**（`IsReadOnly` ＋ `BorderThickness="0"` ＋透明底，取代不可選的 TextBlock）、**附歷史之輸入框＝可編輯 ComboBox**（`IsEditable`，DropDownOpened 填歷史、選中 Delete 刪該筆）；`AskUserQuestion` 只留給真無慣例可循之取捨。
* **優先平台內建控件、不重造輪子**：需求對應框架內建控件者一律先用內建、不自寫等效邏輯（WPF：`GridSplitter` 調寬／`TreeView`＋`HierarchicalDataTemplate` 多層樹／`ContextMenu`＋`InputGestureText` 右鍵選單＋快捷提示／`Thumb` 縮放握把）；例外（如逐字可點需 `Hyperlink` 組裝）須註明為何內建不敷用。內建＝慣例行為、鍵盤可達、少 bug、低維護；自寫等效＝技術債。
* **同 app 內同類互動沿用既有家規（repo 內一致性優先於單頁好用；起因 solLingoIsland #219）**：同一 app 內某類互動（清單排序、卡片操作、篩選切換等）**一經在某頁建立家規**（如清單排序＝toggle 鈕〔各排序鍵一顆、再點翻正反向 ▲/▼、per-scope 記方向〕，NotesPage 立），**新增同類 UI 一律沿用該 repo 既有家規、不另擇控件**（勿一頁 toggle 鈕、另一頁下拉 ComboBox）；plan 設計新互動元件時**起手先盤點 repo 有無同型家規**，沿用或於 design 述明不沿用之理由。起因：#207 影片排序初版用 ComboBox、與筆記頁既有 toggle 鈕家規不一致，下一批 #219 即被 USR 退回重做為 toggle 鈕——一致性應在設計當下沿用、非事後重工。
* **圖示用系統字圖（實測代碼）**：Segoe MDL2 Assets（Win11 亦可 Segoe Fluent Icons）系統字圖，**不用 emoji**；字圖代碼須**實測確認**對應圖形再用（誤填顯示豆腐字／錯圖，且近似字級易誤選——如 `E8B7` 小字級誤似頁面、勿用）。**例外（solTechStyle 覆寫）**：design.md 明選之**非 Fluent 童趣／敘事 solTechStyle**（如 [solTechStyle童話手繪風格]）時，圖示語言改由該 solTechStyle 定——得以 **emoji／彩色字圖**作為一致之圖示語言（惟同工具列／同區域維持一套、風格不混），此時不套 MDL2-only；未選覆寫 solTechStyle 之 Fluent 基調仍一律 MDL2、不用 emoji。選定後**全 app 一致**，不得半 emoji 半 MDL2。
* **平台紀律**：per-monitor DPI aware（manifest 宣告），多螢幕與非 100% 縮放下座標正確；全域熱鍵採系統標準 API（`RegisterHotKey`），禁用低階鍵盤 hook 除非設計明確要求並經 USR 核准。
* **WPF 版面陷阱：`GridSplitter` 之 `ResizeBehavior` 綁的是「列相鄰順序」，插一列即改調整目標（開發碼；起因 solLingoIsland #265）**：`ResizeBehavior="PreviousAndNext"`（及 `Previous*`／`*AndNext` 各式）認的是**分隔線緊鄰的前後兩列**，不是「我想調整的那兩塊」。任何人日後在其相鄰列**插入一列**，調整目標就被**靜默換掉**——編譯不報錯、畫面初始態一模一樣，只有真的去拖才看得出來。**治本＝結構解、非改參數**：把分隔線兩側各包成**語意完整的單一容器**（如「圖塊」vs「內容塊」，內容塊自己是巢狀 `Grid`，其內要加幾列都行），相鄰假設就不復存在；並把該語意寫進 design 契約之 invariant（誰跟誰消長、什麼不得變）。**版面重構是此陷阱之高發期**——實撞 #235 把篩選列搬到分隔線與閱讀區之間，`Next` 目標由閱讀區換成該 `Auto` 列，往上拖只把它撐成空白帶而閱讀區完全不動；因該增量自我歸類為「純版面重構、無邏輯異動」而無任何版面行為測項，缺陷連過 #235／#256／#257 三關進 main、由使用者實機撞見（驗收面之對應把關見 [../../2tech-incrFlow-3code/test/GATE.md] ＜2.5.2節＞「可互動版面元件之行為」）。
* **WPF 事件處理陷阱：視覺樹上溯遇 ContentElement 會擲例外（開發碼；起因 solLingoIsland #208）**：處理 tunnel/bubble 路由事件（`PreviewKeyDown` 等）時，`e.OriginalSource` **可能是 `ContentElement`**（`Hyperlink`／`Run`／`Inline`——逐字可點字幕、可點超連結等場景）；對它呼叫 `VisualTreeHelper.GetParent` 會擲 `InvalidOperationException`（"… is not a Visual or Visual3D"）。凡**沿樹上溯**（找某型別祖先、判焦點落在何種控件）一律用 **Visual/邏輯樹雙軌** helper——`d is Visual or Visual3D ? VisualTreeHelper.GetParent(d) : LogicalTreeHelper.GetParent(d)`——不得用裸 `VisualTreeHelper.GetParent` 迴圈。**此陷阱單元測難攔**：焦點／事件源恰為 Visual 時整條跑得過，只有焦點落在 Hyperlink／Run 那條路徑被踩到才炸，happy-path e2e 亦照不到；命名當下即以雙軌 helper 收斂（同一 repo 若已有滑鼠路徑用的 Visual-or-logical helper，鍵盤路徑務必沿用同一支、勿各寫一份）。
* **Win10＋Win11 雙兼容（硬性）**：Windows 10 與 11 皆現役主流，產物**須同時支援兩者**，不得只顧 Win11 而犧牲 Win10。涉 TFM／WinRT 新 API／最低 OS 版本抉擇時，floor 取兼容 Win10 之值——預設 `net9.0-windows10.0.19041.0`（＝Win10 2004+，涵蓋現役 Win10 與 Win11）；要更寬則另設較低 `SupportedOSPlatformVersion`（如 `10.0.17763`＝Win10 1809）並對較新 API 加版本守衛。用任何較新 API 前先確認 Win10 亦可用。
* **金鑰安全**：外部服務金鑰一律取自環境變數或 OS 憑證保管（Windows Credential Manager／DPAPI），程式檔、設定檔與 repo 不落地金鑰。
* **依賴安全基線**：上線前 `dotnet list package --vulnerable --include-transitive` 0 漏洞，或於 docs/adr 列明豁免（GATE.md ＜1節＞）。
* **桌面 UIA e2e／證據擷取工法**（GATE ＜2節＞ 桌面版；Why：螢幕被使用者並用、Topmost 覆蓋卡、WPF layered popup 使天真截圖／點擊產生**假證據或假失敗**）：
  * **截圖**：主視窗用 `PrintWindow`（`PW_RENDERFULLCONTENT` 0x2）直取視窗表面、不受 Z 序影響；ContextMenu 等 layered popup 對 PrintWindow 回透明，該區改 `CopyFromScreen` 合成。畫布嚴格＝視窗裁切區（DWM 隱形邊框內縮，約左右下 7–8px／上 1px），不留邊緣 padding；**勿用全螢幕／區域 `CopyFromScreen` 當手冊證據**（會滲入他窗）。
  * **點擊**：主視窗預設最小化者，先「還原＋前景確保」重試迴圈（`ShowWindow`＋`SetForegroundWindow`＋WindowPattern Normal＋驗 rect／`IsOffscreen`）；關鍵斷言前驗 `GetForegroundWindow`（防點到 Topmost 覆蓋卡之假通過）。分工：**實體點擊（SendInput）證接線一次、其餘態以 `InvokePattern` 驗行為**，消 SendInput 偶發落空之假失敗。
    * **前景取不到時之分流（滑鼠 vs 鍵盤，起因 solLingoIsland #265／#267）**：`SetForegroundWindow` 常被前景鎖拒絕（實撞：前景由 `GameInputSvc` 之**隱形** `GameInputServiceWindow` 持有，畫面上並無遮擋），繞道依序試 ALT 鍵→`AttachThreadInput`→**最小化再還原**。仍取不到時——**滑鼠操作可續行**，改以 `WindowFromPoint(x,y)` 之 **PidAtPoint 命中斷言**取代前景斷言（直接問 OS「這個點是誰的視窗」，比前景更貼近「會不會被覆蓋」之本意）；**鍵盤操作一律中止**——`keybd_event` 送到的是**當前焦點視窗**、無等價之命中斷言，前景不對就會把按鍵打進別的程式而產生假結果。
  * **取得受測行程：不得只認 `Start-Process` 回傳者（起因 solLingoIsland v4.7.0 發車）**：**成品之啟動路徑可能與 dev build 不同**——launcher／外殼型發佈（Velopack、Squirrel、`AppHost` 轉呼叫等）之外層 exe 會**另起真正的 app 行程後自身退出**（`HasExited=True, ExitCode=0`），此時 `Start-Process -PassThru` 回傳之物件永遠等不到 `MainWindowHandle`。一律改為**輪詢「目標行程名且已有主視窗」之行程**（`Get-Process -Name <app> | Where MainWindowHandle -ne 0`），dev build 亦相容。**發車環對成品重跑同一支腳本是本條之驗收點**——只在 dev build 綠過不算數。
  * **量測型 UI 測試須先確保有足夠可分配空間（起因 solLingoIsland #265）**：驗「A 縮則 B 長」這類**版面消長**時，視窗過小會使版面已頂到 `MinHeight`／已被壓扁，拖曳無空間可分配而量到 0px——症狀是**假失敗**、且極易被誤讀為產品缺陷。開測前須把視窗放大並**讀回驗證尺寸**已達門檻才續行；且**放大須在 App 套用其保存之視窗尺寸（`ui-state` 類）之後**執行，否則會被覆寫。
  * **座標系一致化（DPI，硬性；起因 solLingoIsland #265）**：腳本行程須於**任何座標取用之前**呼叫 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`——DPI-unaware 行程取得的 `GetWindowRect`／`SetCursorPos` 是**虛擬化（縮放後）座標**，而 UIA `BoundingRectangle` 恆為**實體像素**，兩者對不上會使點擊落空、截圖失真，**且全程不報錯**。
  * **`Add-Type` 之 C# 端勿引用 GDI+ 型別**：截圖之 `Bitmap`／`Graphics` 操作留在 PowerShell 端做、C# 只放 P/Invoke 宣告；C# 內引用 `System.Drawing` 型別會撞 `System.Private.Windows.GdiPlus` 參照缺失而編譯失敗。
  * **資料**：測試會改動使用者真實資料（`%APPDATA%` notes.json 等）→ 起手備份、`finally` 還原，且**強制自啟新實例**（沿用中實例之記憶體殘留狀態會在後續 Save 覆寫還原檔）。
    * **樣本資料就地產製、隨備份還原（起因 solLingoIsland #265／#267）**：測試所需之特定樣本（無圖電子書、兩章樣書…）**不得依賴使用者私人資料**——本機恰好有什麼書並不可控，且對他人機器不可重跑。改為由腳本**就地產製最小樣本並植入**（寫入 `%APPDATA%` 之資料檔與資料夾），既已備份還原即不留痕；如此測試跨機可重跑、且不因使用者刪改自己的資料而假失敗。
  * **UIA 樹定位**：WPF `StackPanel`／`Border` 無 automation peer——以 `TextBlock` 文字（`ControlType.Text` 前綴匹配）或 `x:Name`→AutomationId（Button 等有 peer 者）定位。
  * **UIA 驗證細節（可省真截圖之機判）**：① **`Collapsed` 元素離開 UIA 樹**——切換顯示者（子頁籤 pane、模式切換）可據某控件「在／不在」樹中直接斷言可見性，免看畫面。② **原生 `MessageBox`／WPF 對話框**：其內文常落在 `[Pane]` 而非 `Text`（`FindAll` Text 可能撈不到，改讀整棵子樹）；按鈕名受在地化（en＝OK/Cancel、zh＝確定/取消），關閉改送 **`WM_CLOSE`(0x0010)＝Cancel**（locale 無關、比配按鈕名穩）。③ **owned 模態視窗巢在 owner 之下**，以 `Descendants`（非 `root.Children`）＋ProcessId 尋得；模態會阻塞 owner UI 執行緒，故按下開窗鈕的 `Invoke` 可能不返回——另起 runspace 觸發、主緒輪詢對話框。④ **`TogglePattern.Toggle()` 不觸發 Click handler**（RadioButton 用 `SelectionItemPattern.Select()` 會觸發 Checked；ToggleButton 之 Click 須真實 SendInput 點擊）。
